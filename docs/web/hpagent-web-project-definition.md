# HpAgent Web 项目定义（阶段 1）

## 1. 文档目的

本文定义 HpAgent Web 第一阶段的产品目标、渠道关系、核心用户、MVP 使用场景与范围边界，作为后续产品设计、技术方案和验收的共同依据。

## 2. 产品定位

HpAgent Web 是个人 Agent 的正式工作台，面向需要长对话、提交资料和持续委托任务的场景。用户可以在网页中与 Agent 沟通，逐步补充上下文，并查看任务执行过程、历史产物和长期记忆。

HpAgent 的整体体验应接近一个对用户友好、了解用户且值得长期协作的私人 AI 朋友：

- Web 端承接需要专注、信息密度高、过程较长的正式交流与任务委托。
- QQ 端承接随手聊天、快速询问、进度查询和主动提醒。
- 两端属于同一个 HpAgent，而不是两个彼此独立的机器人。

第一版以“类似即时通信的网页对话”为 MVP，不追求一次实现完整工作台。

## 3. 为什么增加 Web？

QQ 适合轻量、即时的交流，但不适合承载个人 Agent 的全部工作过程：

1. **长对话难以组织**：复杂任务通常需要多轮澄清、较长内容和持续补充上下文，聊天流容易被日常消息打断。
2. **文件交互能力有限**：提交多份资料、查看文件状态、下载产物和回顾历史结果都需要更清晰的界面。
3. **执行过程不够透明**：任务步骤、当前状态、工具调用、失败原因和阶段性结果不适合只靠聊天消息呈现。
4. **历史内容难以回溯**：长期任务、历史产物和记忆需要可搜索、可浏览、可管理的固定入口。
5. **正式工作与日常聊天需要不同空间**：用户需要一个可专注处理任务的工作台，同时保留 QQ 自然、低负担的陪伴感。

因此，增加 Web 不是为了替代 QQ，而是补足复杂交互、任务管理和信息沉淀能力，使 HpAgent 从单一聊天机器人发展为可长期使用的个人 Agent。

## 4. Web 与 QQ 的关系

### 4.1 统一之处

- **统一账号**：Web 账号可以绑定 QQ，两个渠道映射到同一个 HpAgent 用户身份。
- **统一 Agent 身份与人格**：两端的名称、角色、交流风格和核心行为原则保持一致。
- **统一长期记忆**：用户偏好、稳定事实、重要经历和长期目标可以在两端被同一个 Agent 使用。
- **统一任务状态**：Web 创建的任务可在 QQ 查询进度；重要进展也可按用户设置通过 QQ 主动通知。
- **统一产物归属**：任务结果、文件和历史记录都归属于同一用户账号。

### 4.2 默认独立之处

- **短期对话上下文默认按渠道和会话隔离**：Web 当前会话不会自动拼接 QQ 最近聊天记录，QQ 日常聊天也不会直接带入 Web 当前会话。
- **聊天列表与未读状态独立展示**：两个渠道保留各自适合的交互形式。
- **通知方式独立配置**：用户可以决定哪些 Web 任务进展需要发送到 QQ。

### 4.3 跨端衔接原则

跨端共享遵循“长期信息共享、当前话题隔离、用户可控衔接”的原则：

- Agent 可以使用两端共同沉淀的长期记忆，但应避免把另一端的私密或无关短期对话生硬带入当前交流。
- 用户可以通过任务编号、会话引用或“继续这个任务”等显式操作在两端衔接上下文。
- QQ 的进度查询与提醒只提供适合移动端快速阅读的摘要；完整过程和产物引导用户回到 Web 查看。

## 5. 核心用户

第一阶段服务的核心用户是 HpAgent 的个人用户，尤其是：

- 已经通过 QQ 使用 HpAgent，希望拥有更稳定、正式入口的用户。
- 经常与 AI 进行多轮、长文本交流，并希望对话可持续回顾的用户。
- 希望未来把资料、任务、产物和个人记忆长期交给同一个 Agent 管理的用户。
- 重视陪伴感和沟通体验，同时要求复杂任务过程透明、结果可追溯的用户。

第一阶段只有“个人用户”一种业务角色，不面向团队协作、企业管理或公开社区。一个账号服务一个自然人，但系统必须支持多个个人账号并严格隔离各账号的数据。

## 6. Web 第一版最重要的使用场景

### 6.1 核心场景：网页长对话

用户登录 Web 后进入对话页面，像使用常见 AI 聊天产品一样：

1. 新建一个对话。
2. 输入问题或任务描述并发送。
3. 实时看到 Agent 的流式回复。
4. 在同一对话中持续追问、澄清和补充信息。
5. 离开页面后再次进入，仍能看到并继续历史对话。

这个场景必须先做到稳定、自然和可信。第一版的产品价值是让用户愿意把原本不适合在 QQ 中展开的长交流迁移到 Web。

### 6.2 MVP 必需能力

- 用户登录并识别统一账号。
- 新建、查看、重命名和继续对话。
- 发送文本消息，接收流式回复。
- 保存消息与会话历史，刷新或重新登录后可恢复。
- 展示基础运行状态，例如“思考中”“执行中”“已完成”“失败”。
- 提供清晰的错误提示和重新发送能力。
- Web 对话可使用同一账号下已经形成的长期记忆，同时保持与 QQ 短期上下文默认隔离。

### 6.3 MVP 验收标准

当用户能够完成以下闭环，即认为第一版核心目标成立：

> 登录 Web → 新建对话 → 连续进行多轮交流 → 中途刷新或退出 → 回到历史对话继续交流。

整个闭环中不丢失消息、不串入其他会话或 QQ 的短期上下文，并能明确看到 Agent 当前是否仍在处理请求。

## 7. 暂时不做的功能

以下能力符合长期方向，但不进入第一版 MVP：

- 完整的文件上传、文件解析、文件管理和在线预览。
- 独立的任务中心、复杂任务编排、子任务管理和人工审批流。
- 工具调用全过程、思维过程或底层运行日志的完整可视化。
- 产物中心、版本管理、在线编辑、分享和协作。
- 长期记忆的可视化浏览、编辑、删除和精细权限控制。
- Web 与 QQ 短期上下文自动合并，或无条件同步所有聊天记录。
- 聊天模式、模型切换，以及 Agent 人格、Prompt、模型和工具的自定义配置。
- 语音、视频、多人会话、群聊和团队空间。
- 多 Agent 可视化协作与 Agent 市场。
- 复杂通知规则、日程中心和多渠道通知编排。
- 会员、计费、配额、邀请和组织管理。
- 面向移动端的原生 App；第一版仅保证基础网页可用性。

“暂时不做”不代表否定这些方向，而是为了让第一版集中验证一个问题：用户是否愿意把 Web 作为与 HpAgent 进行正式、持续对话的主要入口。

## 8. 第一阶段产品原则

1. **先把对话做好**：稳定性、连续性和表达体验优先于功能数量。
2. **Web 与 QQ 各有所长**：Web 负责正式工作，QQ 负责轻量交流和触达，不要求界面与能力完全一致。
3. **同一个人、同一个 Agent**：账号、人格和长期记忆统一，避免产生两个机器人的割裂感。
4. **短期上下文默认隔离**：减少串话、隐私误用和无关信息干扰。
5. **跨端衔接必须可理解、可控制**：何时共享、共享什么以及从哪里继续，应当对用户清晰可见。
6. **过程透明但不过载**：MVP 先展示有用的状态和结果，不暴露难以理解的内部细节。

## 9. 阶段 1 结论

HpAgent Web 的第一版不是完整的任务管理平台，而是个人 Agent 的网页对话入口。它以稳定的长对话和历史续聊为核心，与 QQ 共享账号、Agent 人格和长期记忆，但默认隔离短期会话上下文。完成这一基础后，再逐步增加文件、任务过程、历史产物和记忆管理能力。
