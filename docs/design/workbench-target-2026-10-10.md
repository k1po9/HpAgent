# HpAgent 工作台布局与样式改造指导方案

本方案依据用户提供的目标图、当前前端源码，以及本次对话中已经完成的实际页面检查和两轮浏览器视觉试验。范围按用户最新要求收敛为：在现有功能上调整布局、组件排布和 UI 样式。

## 1. 改造范围

目标是接近参考图的四栏比例、浅色表面、消息阅读体验和预览面板层级。保留现有 React、Radix、assistant-ui、Zustand、Shell 与 Inspector 架构。

允许调整 CSS、视觉 tokens、用于排布的 JSX、展示组件组合和响应式尺寸计算。允许把现有按钮或标题移动到新的视觉位置，但复用原事件处理和数据来源。

API、业务 Store、SSE、权限、发送与停止资格、版本选择规则、任务状态、生成流程和后端保持现有语义。没有新增依赖或新页面的需求。登录、注册和入口转场不纳入本轮。

| 参考图元素 | 本轮处理 |
| --- | --- |
| AI / 空间 / 任务 / 成果四个导航入口 | 保留当前 AI / 空间 / 任务三个入口，调整尺寸、图标和选中态 |
| 用户照片与在线绿点 | 使用本地用户图标作为头像，不新增照片或在线状态 |
| 多条勾选式执行步骤 | 将当前状态、spinner、phase / summary、详情与停止入口排成卡片，不新增步骤模型 |
| Markdown 成果文档 | 保留当前 HTML 成果及预览类型，只调整外部面板与卡片样式 |
| 文档说明、大小等元数据 | 仅排版现有可得字段，缺失字段不占位、不编造 |
| “保存到空间” | 保留“保存源码副本到空间”的实际名称、动作和语义 |
| 更多、分享等图标 | 仅保留已有可用操作，不增加空菜单或装饰性按钮 |

因此完成标准是现有产品的布局和视觉接近目标，不要求图中所有元素、内容或状态完全一致。

## 2. 视觉规格与实测依据

基准尺寸为 1672 × 941。目标值根据图中分隔线估算；当前值来自实际页面 DOM。建议值已在宽屏视觉试验中验证，正式实现仍需交互和响应式回归。

| 项目 | 当前实测 | 改造起点 |
| --- | --- | --- |
| 主导航宽度 | 64px | 104px |
| 上下文侧栏宽度 | 256px | 280px |
| 右侧面板宽度 | 420px / 扩大后 520px | 保留 420px / 520px |
| 打开普通右侧面板时的中央区域 | 932px | 868px |
| 对话标题区域 | 顶栏 72px + 重复标题栏 57px | 合并为一层，约 72px |
| 宽屏空闲输入区高度 | 215px | 66–72px，内容多时增高 |
| 正文 | 约 15px | 16px，行高约 1.8 |
| 头像与消息间隔 | 无可见头像 | 40px 头像 + 14px 间隔 |
| 消息间距 | 分散在多层规则中 | 24–28px |
| 表面与控件 | 已有浅色蓝色主题 | 白色主画布、极浅蓝灰侧栏、细边框、轻选中底色 |

颜色继续使用现有语义 tokens：正文 #182235、次要文字 #67758c、边框 #e3e9f2、主色 #1267df；用户消息和选中背景可在现有浅蓝基础上微调。正文、卡片和输入外壳圆角先取 8–12px。一般按钮高度 36–40px，主要按钮和手机可点击区域至少 44px。字体沿用现有中文无衬线回退。

对照材料：[目标图](../../artifacts/product-acceptance/ui-target-20261010/target.png)、[当前同屏](../../artifacts/product-acceptance/ui-target-20261010/current-artifact-top-1672.png)、[第一轮试验](../../artifacts/product-acceptance/ui-target-20261010/round1-artifact-1672.png)、[第二轮试验](../../artifacts/product-acceptance/ui-target-20261010/round2-artifact-1672.png)、[1440px 试验](../../artifacts/product-acceptance/ui-target-20261010/round2-artifact-1440.png)。尺寸见[当前记录](../../artifacts/product-acceptance/ui-target-20261010/geometry.json)与[试验记录](../../artifacts/product-acceptance/ui-target-20261010/experiment-geometry.json)。

试验确认了四栏和紧凑输入区的方向；第二轮在 1672px、1440px 下未发现页面溢出或所检查输入控件的水平裁切。试验中出现的头像跨行空白、侧栏宽度覆盖冲突、扩大阅读按钮挤窄正文问题已经经过看图修正。现有试验使用临时 CSS 和 DOM 排布，正式实现应使用 React 组件组合，不能复制 DOM 搬移脚本。

## 3. 具体修改指导

### A. Shell、导航与侧栏

涉及 `web/src/components/shell/AppShell.tsx`、`useShellWidth.ts`、`web/src/components/ConversationSidebar.tsx`、`styles/tokens.css`、`styles/shell.css`、`styles/unification.css`。

- 将主导航调整为 104px，显示 HpAgent 字标；保留三个现有入口。导航项约 80px 高，图标约 26px，标签约 14px，选中态使用浅蓝底和左侧蓝线。
- 对话侧栏调整为 280px。标题、新建按钮、筛选框和日期分组形成明确的垂直节奏。新建按钮独占一行、高 44px；筛选框约 40px；对话行约 44px。
- 保留“筛选已加载对话”含义与加载更多、刷新、失败提示。若展示时间，直接格式化现有 updated_at，保持标题可截断、完整名称可读取。
- CSS 与 JS 使用同一份尺寸定义。当前折叠公式硬编码了 64 / 256 / 560，修改视觉宽度时必须同步，不能只加 CSS 覆盖。

中央最小宽度先取 600px。普通面板四栏所需空间约为 104 + 280 + 600 + 420 + 4 = 1408px；扩大面板时约为 1508px。宽度不足时沿现有抽屉机制收起上下文侧栏。Inspector 的窄屏模态机制和手机底部导航继续使用原有实现。

### B. 唯一对话顶栏

涉及 `AppShell.tsx`、`ChatPane.tsx`、`conversation/ConversationHeader.tsx`。

将现有标题编辑组件组合到 Shell 顶栏中，保留一份对话标题和原改名入口。左侧标题约 22px，右侧放现有“从回复生成 HTML”“对话资料”和执行查询。标题较长时截断，宽度不足时让操作自然换行；本轮不需要增加新的菜单功能。

改名表单及保存、取消、忙碌和失败提示仍由当前组件管理。不要通过永久隐藏整块 ConversationHeader 来消除重复标题，也不要画出没有操作的箭头。新对话、加载失败和其他页面继续显示各自实际标题。

### C. 消息阅读区

涉及 `web/src/adapters/assistant-ui/HpThread.tsx`、`styles/conversation.css`、相关 Markdown 排版样式。

两种消息沿同一个头像列排布：本地用户图标 / 机器人图标、间隔、正文。用户正文使用浅蓝气泡，助手正文采用无外框的文档排版。成果卡、附件和执行块沿正文左边缘对齐。头像只占当前行，避免跨多个隐式 grid 行造成额外空白。

正文使用 16px / 1.8 行高，规范段落、列表、标题、表格和代码块间距；长代码和表格在自身区域横向滚动。时间如需展示，只使用现有消息时间字段，作为次要文字。没有照片和在线状态装饰。

继续使用原 assistant-ui 运行时、单一消息视口及历史锚点恢复；布局变化不替换消息数据适配或滚动系统。

### D. 紧凑输入栏

涉及 `HpThread.tsx`、`ChatPane.tsx`、`conversation/ConversationResources.tsx`、`styles/conversation.css`。

宽屏空闲态把文本输入、附件、历史附件选择、使用资料、执行模式、发送组织在同一条轻边框表面，约 66–72px 高。输入控件去掉重复内框；工具图标和标签尺寸统一。手机或中央区域较窄时采用输入行 + 工具行，保持可用的文本输入宽度。

已有附件、授权资料 chips、查询 / 上传错误、停止中等状态仍完整展示，并允许容器自然增高。多行输入可以增高，达到上限后内部滚动。不能用固定高度和 overflow:hidden 裁掉状态、输入文字或按钮。

如果需要拆分 ConversationResources，只拆分展示区域与组合位置，保持它的数据加载、权限处理和弹层生命周期。重复管理入口只有在现有等价入口明确可达时才可合并。优先保留当前操作名称，不以缩短文案改变功能含义。

不修改 IME、Enter / Shift+Enter、草稿保存、幂等提交、附件就绪判断、快速 / 深度能力开关、发送 / 停止资格；空白输入仍显示禁用发送态。

### E. 现有执行状态的卡片样式

涉及 `components/run/ExecutionBlock.tsx`、`components/RunStatus.tsx`、`styles/run.css`。

将现有内容重排为轻边框卡片：上方 spinner / 状态名称，中间当前已有 phase / summary、连接恢复或失败说明，下方执行详情和已有停止 / 重试按钮。终态可以更紧凑；历史执行详情继续使用轻量入口。

状态文字、出现条件、操作资格与回调保持原实现。使用已有颜色区分运行、失败、已停止等状态。本轮不新增勾选步骤、阶段投影、计时器、百分比或预计时间，也不修改 traceStore、SSE 或 workbench。

### F. 成果卡与 Inspector 外壳

涉及 `components/artifact/ArtifactMessageItems.tsx`、`ArtifactInspector.tsx`、`shell/InspectorHost.tsx`、`shell/Surface.tsx`、`styles/artifact.css`。

成果卡统一图标区域、标题、现有 HTML / 版本 / 状态字段、打开入口和内边距。使标题与次要元数据明显分层，按正文列对齐。保持每个 artifact_id 的独立身份，不能为了画面简洁合并不同成果或隐藏真实版本状态。

右侧面板保持现有内容类型、Tabs 和业务逻辑，整理为头部信息、Tabs、可滚动内容与操作区域。将扩大阅读放入头部，减少正文前的额外空白；下载 HTML 和保存源码副本可移到固定可见的底部操作区。现有版本提示、任务原引用、错误反馈和修改指令继续可见、可达；本轮保留修改表单的现有展开方式。

Surface 如需增加 header actions 或 footer，只调整呈现插槽与布局，不改原生 dialog、模态阈值、嵌套层协调、焦点返回和关闭 / 返回行为。固定底部操作区采用明确的 flex / grid 分区，正文 min-height:0 和独立滚动，避免覆盖正文或修改表单。

HTML iframe 保留原 srcDoc、内容和 sandbox。只调整外框、可用宽高和与周围内容的间距；不改生成模板、不注入文档内容、不把预览改成 Markdown。原始 HTML 内部排版与目标图不同，属于本轮允许的差异。

## 4. 样式组织与实施顺序

当前视觉规则分布在 base、shell、conversation、unification、visual 等样式文件中。仅整理本轮涉及的重复属性，将确定后的规则放回所属组件样式和 tokens；不扩大为全仓样式重构，不再新增一层长期全局覆盖。

| 轮次 | 修改内容 | 看图重点 |
| --- | --- | --- |
| 第一轮 | 宽度定义、三入口导航、侧栏、唯一顶栏 | 与目标图比较四栏比例、标题层级、控件位置和可阅读宽度 |
| 第二轮 | 头像消息、Markdown 消息排版、输入栏、现有执行卡 | 比较消息对齐、段落间距、输入区高度；检查状态是否被裁切 |
| 第三轮 | 成果卡、Inspector 外壳、涉及规则整理 | 比较卡片分层、Tabs、预览可用面积和底部操作；验证共享 Shell 在空间和任务中的外观 |

每轮修改后都必须实际打开页面、截图并查看截图，再根据看到的问题定向修改。保留上一轮与最终图及简短修正记录。不能以代码阅读、DOM 尺寸、测试通过或历史截图替代本轮实际视觉检查。

## 5. 验收标准

### 视觉与响应式

- 使用同一组实际记录、相同滚动位置，在 1672 × 941、1440 × 900 下对照原图和修改前截图；内容长短不作为相似度要求。
- 检查 1366、1280、1024、390px；在实际折叠边界附近各加一个尺寸，验证 CSS 与 JS 的模式一致。
- 检查长标题、空对话、长消息、表格 / 代码、多个成果、输入多行、待上传 / 失败附件、资料 chips、错误和执行中的外观。
- 页面无横向溢出；控件和提示不被父容器裁切；关闭、返回、Tabs、输入及底部按钮可见且可点击。
- 空间和任务继续使用现有页面结构，检查共享宽度、字体、按钮、面板调整是否造成布局回归。认证页面及转场没有视觉回归。

### 原有行为回归

验证对话切换与改名、草稿和阅读位置保留、IME 与 Enter / Shift+Enter、资料入口、附件选择和移除、发送 / 停止 / 重试、Inspector 打开 / 关闭、扩大阅读、Tab 与版本选择、下载及保存源码副本、弹层和焦点返回。检查 loading、disabled、hover、focus 和 reduced-motion。

按变更运行现有相关组件与浏览器回归、typecheck、build 和格式检查；只有实际修改了行为契约或发现缺陷时才新增有意义的测试，不为颜色、间距和静态样式编写镜像测试。

业务检查使用隔离测试环境。检查状态可以使用现有测试夹具，但必须注明数据来源；最终效果截图以真实渲染的应用为准，不把夹具或示例内容接入生产入口。

### 交付物

1. 仅包含布局、呈现组件及样式的前端变更。
2. 原图、同条件修改前 / 最终截图、各轮看图修正记录。
3. 必要的尺寸与局部裁切记录、实际执行的检查结果。
4. 清楚标注允许保留的差异：三个导航入口、当前执行摘要、真实状态 / 元数据、HTML 预览内部内容。

## 6. 可直接使用的实施任务说明

> 按本方案调整 HpAgent 现有工作台的布局和 UI 样式。先阅读对应组件和原目标图，再启动实际前端，保存同条件基线截图。沿 Shell 与顶栏、消息与输入、现有状态卡与 Inspector 的顺序迭代，每轮都打开页面、截图、人工查看并修正。仅复用已有功能、数据和事件处理；不新增导航页面、Markdown 成果、多步骤进度、计时等功能，不修改 API、业务 Store、SSE 或后端。保持当前交互与权限语义，同步 CSS 与响应式尺寸计算，完成相关回归并提交可对照的最终截图。

本方案生成时仅提供指导，沿用此前的视觉试验。随后按用户“开始第一轮”的指示，实施了宽度、导航、对话侧栏与唯一顶栏，见[第一轮记录](../../artifacts/product-acceptance/ui-layout-round1-20261010/README.md)。按“第二轮实施”的指示，完成头像与 Markdown 消息、紧凑输入栏及现有执行状态卡，见[第二轮记录](../../artifacts/product-acceptance/ui-layout-round2-20261010/README.md)。按“第三轮实施”的指示，完成成果卡及 Inspector 头部、阅读区与底部操作排布，见[第三轮记录](../../artifacts/product-acceptance/ui-layout-round3-20261010/README.md)。三轮均经过实际截图迭代和相关回归；本方案限定的布局与样式范围已实施，未新增目标图中尚不存在的功能。
