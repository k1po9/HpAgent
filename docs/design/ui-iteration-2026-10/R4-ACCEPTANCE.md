R4.1 至少覆盖 Run 的 I01–I10、I13–I17、I19–I20；尚未接入对象在报告中标明，不伪称四类全覆盖。R4.2 补齐四类、I11–I12 与完整 I18，复验相关共享路径。

性能必须记录设备/浏览器、视口、采样时长、活跃对象数和测量方法；没有测量不写稳定60fps。真机 IME/软键盘、其他浏览器与真实供应商若未测，逐项写 not-run，不用模拟替代。

## 每次人审包

- 可操作的真实 React HTML 入口与同数据对照；清楚说明正常真实 API/Fake、确定性浏览器夹具各自范围。评审控制不能进入产品。
- 桌面正常开关、快切、慢请求、关闭重开、窄屏/减动操作说明；业务正确与体验判断分列。
- 实际自审：问题位置/情景→原因→修复→复验，而不是只给审美分数；可用自动化时序与关键帧核查因果。按用户最近偏好不强制录像。
- 反馈表：用户原话、对应修改、证据、是否待复审；未获认可的意见不自行关闭。
- 明确当前 stage、源码指纹、测试/未测项、启动恢复命令与已知限制。

R4.1 人审关注“对象从哪里来、何时进入、关闭是否真的完成且连贯”；R4.2 关注“四类一致性、版本与返回是否好用、与发送/执行/继续阅读的整体连贯性”。局部认可不代表整轮接受。最终只在用户明确接受且阻断项关闭后写 R4 DECISION，冻结交互合同与源码，交回总调度；不自动进入 R5。
