## 3. 范围边界

### 本轮允许

- 排版、字号、行距、局部留白、描边、阴影、圆角、材质和操作视觉层级。
- 局部语义 DOM 调整、组件作用域样式及必要的静态展示抽取，保留可访问名称、焦点、键盘和业务入口。
- Conversation 白瓷选中表面与细橙归属线；保留实际选择、搜索与分页。
- 对 Run 现有文本/操作做静态层级优化，为 C 留出结构，但不添加假的六态或动作权限。
- 使用原生真实组件的开发预览/测试 harness；受控数据明确标识，与真实 API 证据分开。
- 逐组件清理本轮涉及的重复样式，保留前后对照。

- A 的接力/轨道、B 的银丝/Arrival Gate/Soft Close、C 的新状态映射与连续动画、Mercury 收纳入口和控制器。
- X/back 语义调整、审批订阅重构、发送确认事件桥；这些属于后续轮次。
- 重建四区、领域 Store、后端 API、授权/幂等逻辑；更换框架或引入新视觉依赖。
- 全站 CSS 重写、全站容器统一卡片化、主题重新发散。
- 虚构百分比、会话摘要、阶段、审批、成功或成果数据。
- 把实验 HTML 当生产页面，或为截图临时在浏览器注入替代 CSS/移动真实 DOM。
- 自动合并、发布、删除 Skill 或覆盖历史证据。

## 4. 两个候选及假设

候选名使用 S1/S2，避免与 EXP-02 A/B 混淆。

| 项目 | S1 开放正文＋对象卡（推荐探索） | S2 轻边界阅读面 |
| --- | --- | --- |
| 假设 | 降低普通回答容器重量，让成果/执行成为明确对象 | 连续而轻薄的纸瓷承载能增强归属，并保持长文舒适 |
| 助手正文 | 开放排版、极轻或无外框，依靠字级与段落节奏 | 轻阅读面、弱边界、低阴影，避免每段再套框 |
| Run/Artifact/File | 独立有界对象，类型/标题/状态/主要操作明确 | 同样明确，与正文阅读面有可辨的材质或密度差别 |
| Composer | 独立行动面，焦点清晰，常态不发光 | 同一行动身份，与阅读面形成前后层次 |
| Inspector | 清楚对象身份、关键事实、操作和元数据分组 | 同事实与功能，比较阅读面如何延续到详情 |
| 不接受 | 把无边框做成松散、无法辨认角色的文字堆 | 厚描边、重阴影、白卡套白卡、所有信息同权重 |

两候选保持相同数据、字体基线、功能和四区比例，以阅读面/对象层级为主要变量；不能只改变2px圆角就声称两个方案。不得把两候选混在一起后只交付一个。

设计起点（均为待验证建议，不是已批准像素）：正文15–16px、行高约1.7–1.85；主体与对象标题有明确级差；移动输入保持至少16px；次要信息适度弱化但满足对比度。字体优先复用现有系统栈，记录实际回退，不能在未加载时声称已使用 Inter。

品牌橙用于行动，语义色各司其职。静态表面可有精细冷瓷/银边，禁止持续橙光、大面积玻璃、强渐变和无意义科技装饰。

## 5. 候选的工程承载

优先复用同一套生产组件，通过局部作用域样式表达候选差异。可使用开发专用 variant 入口/构建配置进行同屏或切换预览；此入口不能写入业务路由、变成正式用户设置、在两候选间丢草稿或重挂载运行链。

实施者选择最小实现方式，并写清：默认页面是哪种、S1/S2 如何访问、关闭预览如何回到基线、是否影响生产构建。人审前不得把某候选标作已批准默认。确保基线和两候选可以复现，不要求复制两套业务组件。

至少提供一个真实应用集成预览。开发 harness 可补充长内容/极端状态，但不能成为唯一交付。若本机无法启动真实 API，先完成可独立的组件工作和受控预览，明确集成验证 blocked；不得据此标本轮验收通过。

## 6. 场景与数据合同

准备以下固定场景，S1/S2 使用相同记录、状态、滚动位置、时间显示与 viewport。数据来自专用隔离测试环境或明确标识的受控 fixture；不得污染日常业务。

| ID | 场景 | 要观察的设计问题 |
| --- | --- | --- |
| ST01 | 空对话 | 视觉重心、输入邀请、无装饰堆砌 |
| ST02 | 短问答＋真实可打开的成果对象 | 正文/成果/主要行动是否分明 |
| ST03 | 长回答：标题、列表、引用、表格、代码、中英文 | 阅读节奏、文字密度、横向溢出 |
| ST04 | 多轮交流、多个对象、长标题 | 是否仍能识别角色和归属，是否卡片堆积 |
| ST05 | Composer 草稿、键盘焦点、附件未就绪/失败 | 行动层级、禁用原因、按钮与文字可辨 |
| ST06 | 当前 Run 状态及失败/连接退化提示 | 信息、告警和动作层次；不添加 C 新协议 |
| ST07 | Run Inspector 与 Artifact 预览 | 详情密度、iframe 稳定、版本/操作可达 |
| ST08 | File/Task Inspector、嵌套 Surface | 共享材质是否兼容高密度及表单 |
| ST09 | Workspace/Tasks、登录与错误 | 全站相邻区域不退化，不要求本轮重设计 |

证据预算：

- 核心对照 ST02/ST03/ST07，在1680×1000与390×844上提供 baseline/S1/S2，共18张核心图。
- ST02/ST07 两候选在1280与780宽度补充检查；1279/1280断点、短屏、200%文字、长标题和减动做定向验证。
- ST01/ST04/ST05/ST06/ST08/ST09至少检查代表状态；按发现问题留图，避免无目的生成数百张。
- 某组合不适用时注明原因；环境缺失写 blocked，不能省略后称完整。
- 默认截图用减动稳定状态，另验证正常模式仍可操作。R1无需新增特效录像；短操作录像可以辅助人审，但不冒充动态设计已经完成。

## 7. 实施步骤和自审

1. 记录 HEAD、分支、dirty diff、Skill 来源和环境。核实是否有其他窗口修改前端。保留无关改动。
2. 看当前截图与参考图，写一页设计假设：当前最明显的3–5个问题、两候选区别、拟改组件与变量。然后继续实施，不停在计划阶段。
3. 先做 ST02/ST03/ST07 的桌面与手机切片，查看实际渲染图，不靠代码想象效果。
4. 实现两候选并修正明显排版/材质问题，维持业务节点身份和入口。
5. 自审第一遍：冻结契约、层级、密度、对比度、中文排版、长内容、候选差异。
6. 自审第二遍：导航/草稿/IME/焦点/Inspector/iframe/移动和减动；有问题修改后复验相同场景。不为凑轮数制造问题。
7. 生成对照索引、自审记录、技术验证、HANDOFF；交付待人审。未达到提交标准时说明问题并继续本轮修复，不自行进入 R2。

自评维度为层级、排版、材质、状态辨识、整体一致性；运动因果本轮 N/A。每项1–5分且附具体图像依据，推荐候选各项建议≥4。分数只表达代理判断，不代表用户接受。S1不应因被推荐而获得先验胜出地位。

## 8. 验证范围

按实际改动选择有意义检查，不能只新增镜像实现的测试来增加数量：

- typecheck、受影响文件 lint/format、build、diff格式。
- 复用 App/恢复、HpThread.ui2、ConversationSidebar、RunStatus、Inspector/Surface、受影响对象组件的既有单测。
- 浏览器覆盖会话切换与草稿、IME Enter/Shift+Enter、附件禁用原因、发送/停止原语义、Inspector Tabs/焦点/扩大阅读、嵌套 Surface Escape、Artifact iframe 不因外观切换重复加载。
- 文字常规对比≥4.5:1，大字/必要图标边界≥3:1；禁用、透明叠色、焦点与Portal分别解释测量边界。
- 几何检查包括页面无横向溢出、操作未被遮挡、触摸目标、内容未被不必要截断。
- 相关检查通过后，只有新变更/失败/未决风险才扩大或重复检查。

必须先读测试环境隔离要求：既有脚本可能启动服务、迁移并写入账户/Run；部分 fixtures 会 TRUNCATE。不得直接使用默认业务 DSN，不能假定2026-10-12的8196测试服务仍安全可用。核实专用库、Redis、文件目录、端口及写入范围后才能运行。已有默认证据路径可能覆盖历史，必须改到本轮 attempt 目录。

无浏览器/数据库/真机时明确 blocked/not-run，继续能独立完成的工作。不得写“全部通过”或引用历史次数充当本轮结果。
