## 代码与契约

- `WorkspaceDiscovery` 提供所有者的名称、类型、来源类别、Task、Run、日期、摘要过滤，按稳定 node ID 分页。Run Agent 检索先限于 `run_resource_candidates` 固定集合，再查当前 `list_metadata`；摘要还要求当前 `read_content`。结果不提供文件正文或存储键。独立的 Research Markdown 摘要索引绑定 `file_id` 和 SHA-256，API 返回摘要所对应的 hash；只为指定 Research 发布 operation 创建索引。
- 保留诊断按 file_id 统计活动 entry、修订、消息、Run、固定候选、访问、pending 发布与当前 destination；Workspace 空间统计按唯一 ready `stored_files` 行计量，多个入口不重复计字节。UI 明示移除入口后仍须释放其他引用并由统一 GC 回收。未开放直接物理删除或自动修剪历史。entry trace 返回 source Run/Task、发布/修订/保存 operation、授权拒绝及候选固定/物化/读取时间；超过 100 条 Run 使用事实时显式标记截断。发布、保存和版本事实仍分别来自原有持久表。API 记录授权/候选拒绝、CAS 冲突与停止未确认的结构化事件，GC 物理删除失败记录可重试事件；日志仅含代码和对象 ID，不含正文或存储键。
- 候选生成改为从有效授权目标递归到活动后代，保持 500 项 / 512 KiB 上限与显式拒绝；避免为整个 10k 树构建反向祖先集合。`run_resource_candidates.materialized_at` 只在实际复制完成后登记，与 fixed/read 分离。
- API 与 Web 增加搜索、保留可见性及 trace 入口。服务启动只读核对迁移版本与校验和；schema 不匹配明确报错，不执行迁移或清库。旧 Research 测试中“新聊天无授权可发现独立 Task 输出”的断言改为要求不可发现。

## 实测与验证

- 环境：本机 Docker PostgreSQL（localhost:5434）、Python 3.12 venv、真实 API/worker DB 角色、Temporal（localhost:7233）、Chromium Playwright；测量在隔离库内。规模 fixture 为一个 7-byte ready `file_id` 被 1k/10k 个活动 entry 引用；用于验证零复制计量、分页和上限，不代表 10k 个不同文件的磁盘吞吐。
- 最终代码下，1k/10k 条目搜索 `report-` 首个 100 项分页耗时分别 **0.0641 s / 0.0392 s**；Python `tracemalloc` 峰值 **176,740 / 165,229 bytes**；`physical_bytes` 均为 **7**，分页均有下一页。单批插入 1k 条目耗时 **0.6749 / 0.6148 s**。未测整机 RSS、真实文件复制总量或 p95。
- 10k 目录递归 grant 创建 Run：旧查询显式拒绝但耗时 **30.6298 s**；改写后显式拒绝且耗时 **0.0865 s**，提示 `candidate count exceeds 500; narrow the grant`。候选创建失败没有截断成 500 项执行。
- 隔离库空库迁移 001～052 成功；API 与 Worker 角色的只读 schema gate 成功。注入隔离库假迁移记录后 gate 报 `schema mismatch`，移除探针后恢复；未自动清库。真实 PostgreSQL P0～P5、API、Research 组合回归 **30 passed, 1 skipped**（skip 原因是该轮未设 `TEMPORAL_HOST`），随后在专用 namespace 单独运行真实 Worker/Activity 保存重试 **1 passed**。P5 摘要授权、零复制空间与 trace 定向测试通过；改写候选查询后 P2/P5 回归 **8 passed**。前端 82 单测、lint、typecheck、Python 改动文件 Ruff、`git diff --check` 通过。Chromium P1/P3 两条业务场景 **2 passed**。
