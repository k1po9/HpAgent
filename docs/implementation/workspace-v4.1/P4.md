## 实施内容

- 迁移 045～047：Task 增加稳定输出目录 ID、create/update 类型、required 标记和策略版本；版本更新额外绑定 entry ID。Run 创建时存储目标目录、目标 entry、操作类型、output kind、策略版本、required、稳定 operation ID 和预期修订/hash。历史基线单独保存所选 Run、entry、不可变 file ID、摘要快照、SHA-256、选择理由和预算。保存及版本操作登记手动/Task 自动来源与 source Run。
- Task 触发在同一事务中建立资源候选、固定保存意图，再入 Outbox。输出目录与输入资源使用长期 Task grant；输入授权只开放元数据和正文读取。输出目录重命名保持 ID；仍被 Task 绑定的目录删除被拒绝。目标变更增加策略版本，仅影响后续 Run；旧 Run 保留冻结意图并在提交时重新校验当前权限。UI 显示并可设置 Task 时区与每日时间；Run 文件名按其创建时对应 Task 时区计算日期。
- Research `prepare` 在 planning 前从固定 Run 候选中选最多 3 份同 Task 历史快照，总编码预算 8192 bytes。先以候选及元数据定位，再要求当前 `read_content`；快照固定后重试复用，并再次校验内容权限、entry 存活与 hash。planning 用所选历史 claims 形成有界的变化问题，合成输入只附入选快照，daily diff 使用同一基线，不再查询任意同 Task 最新报告。无合法历史时保存空基线并按无历史执行。
- Workflow 顺序为报告持久化、daily diff、发布 HTML/Markdown、Workspace 保存、完成。保存 Activity 独立于 Research 合成；临时故障重试保存。Workspace entry 与历史 operation 结果同事务登记，Run 保存意图状态随后可重放补齐。完成 Activity 同时核对 required 意图和对应已提交 operation；只有状态位而没有 operation 仍拒绝 completed。取消/失败已获胜时不推进 completed。永久故障或重试耗尽使用 `workspace_save_failed` 终态及保存错误码，保留已发布文件。
- 同日文件名包含 Task 时区日期和完整 Run UUID，内容 hash 相同仍形成不同 Run、报告及条目。`update_content` 固定 entry、基线修订与 hash，使用 P3 CAS 内核；版本冲突不静默另存。Task/Run UI 提供输入读取授权、目标目录/版本条目配置、路径展示、报告正文、发布文件、保存状态、失败码及独立手动另存入口。预授权自动保存不逐次弹审批。

## 幂等与故障边界

- 保存 operation ID 为 `workspace-save:<run_id>:research_markdown`；目标、类型、策略版本与 update CAS 基线在 Run 创建时固定。重试不读最新 Task 目标生成新身份。历史成功结果在权限检查前返回，避免已提交 operation 在撤销或 Run 完成后重放产生第二个 entry。
- 已发布 Markdown 是独立 ready `stored_files`/`run_files` 事实；保存失败时仍可由 Run 页面下载，并可由用户以新 operation 手动另存。自动与手动保存都走 WorkspaceCatalog，operation 记录来源。
- 历史快照是重复执行基线，不授予永久权限。授权撤销、entry 删除或目标删除使新读取/提交失败关闭；不会自动转向新目录或根。
