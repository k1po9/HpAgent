## P1 代码与 schema

- `042_workspace_v41_p1.sql`：`account_workspaces` 每账户唯一；`workspace_nodes` 存根、目录、文件条目及 tombstone；同父目录的文件和目录共享唯一 `name_key`。复合 FK 保护账户、Workspace、父节点与文件；触发器校验父目录活动状态、根不可变、非空目录不可删除及无环。对 Workspace 行加锁序列化并发移动。`workspace_save_operations` 持久化保存操作的幂等身份。
- `WorkspaceCatalog`：幂等初始化根及资料/任务/成果；首次初始化后不补建被删除的默认目录；支持任意层级目录、重命名、移动和移除。名称用 NFC 与 casefold 生成同级键。保存仅新增指向现有 ready `file_id` 的 entry；已发布 output 需有 `run_files` 发布依据。文件来源、hash 和对象字节不随 entry 操作改变。
- `FileService` 与 `FileCleanupService` 使用同一 `claim_file_deletion` 内核。消息、Run、活动 Workspace entry、既有 destination/revision 和 pending 发布操作均保护对象。新增引用与 GC 在 `stored_files` 行上竞争锁；删除先登记状态，再执行可重试的物理删除。普通文件删除保留原 API 入口，但已改走该内核。
- API 新增 `GET /api/v1/workspace`、目录创建、文件保存、节点移动/改名及移除。Web 增加长期目录浏览、来源显示、保存、移动、改名、移除；当前 Run 临时资源在 UI 中另列。聊天附件和 Research 输出可保存到所选目录。Agent 仍仅使用现有 Run 授权文件范围。
- 删除旧 `save_persistent_file` 工具与 activity、`PersistentFileService`、旧 logical-path 下载路由、旧审批卡、旧 F4 审批浏览器脚本与对应过时测试。`persistent_file_destinations.logical_path` 从 schema 删除；既有修订表作为保留引用继续参与 GC。通用审批服务保留，但不再返回旧 logical path 字段；本阶段没有给 Agent 开放账户 Workspace。

## 开发环境重建

本轮未清空现有开发数据库或存储。旧数据不迁移；如果开发者明确决定重建现有 `hpagent` 数据库，先停止依赖它的 API/worker，再手工执行以下破坏性命令：

```sh
docker exec hpagent_web-app-postgres-1 sh -lc 'dropdb --force -U "$POSTGRES_USER" hpagent && createdb -U "$POSTGRES_USER" hpagent'
docker compose --profile web up hpagent-migrate
```

本轮隔离测试数据库可按需单独删除：

```sh
docker exec hpagent_web-app-postgres-1 sh -lc 'dropdb --force -U "$POSTGRES_USER" hpagent_p1_20260926'
```
