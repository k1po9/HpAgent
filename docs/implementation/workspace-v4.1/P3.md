## P3 变更

- `044_workspace_v41_p3.sql`：删除修订全局 `UNIQUE(file_id)`，不同 destination 可引用同一 ready 对象。当前指针通过延迟复合 FK 与 `(account,destination,revision,file,hash)` 修订一致；修订行不可更新/删除，插入时验证对象 ready 与 hash。Workspace 的原位升级是唯一允许的内容身份变化；已有部分唯一索引确保每 destination 最多一个活动 entry。历史操作表以 `(account,operation_id)` 保存冻结意图摘要与原成功结果。移除不再承担幂等权威的 `last_operation_id` 字段。
- `WorkspaceCatalog`：同一事务锁定 entry，创建 destination 和 revision 1，原 entry ID 不变且不复制 F1；并发升级收敛。`update_file` 要求 Run 固定该 entry 的预期 file/revision、当前 `update_content` 授权、有效且未取消的 Run、同 Run 已发布 ready 输出、预期 revision/hash。提交只登记修订并推进指针，不调用发布器或复制字节。已完成的合法 Run 可由所有者提交其已发布输出；取消中、已取消及失败 Run 不可提交。CAS 冲突返回当前版本与已发布输出 ID，不自动覆盖或更换基础版本。
- 历史 operation 在权限及 CAS 检查前查询，重放原结果；同 ID 不同意图拒绝。OutputPublisher 的持久化意图和确定性对象身份覆盖发布故障窗口；发布已完成、修订未登记时，保存服务使用原输出与稳定 operation ID 重试。修订表表达逻辑版本；stored_files 原始 Conversation/Run 来源不被改写，账户级 parent lineage 仍表示对象生成关系。
- Workspace 树、版本查询、当前版本、来源和下载均使用 entry/destination ID。新增原位升级、历史、Run 已发布输出及版本提交 API；Web 可浏览历史、选择 Run 输出、提交更新、显示冲突并提示另存。目录改名/移动只更新节点元数据。GC 增加固定 Run 候选和访问引用检查，继续保留历史修订、当前指针及 pending publish 意图。
- 旧路径接口在 P1 已删除，本轮核对 `src`/`web/src` 没有 `logical_path` API、兼容 resolver、旧路径别名或双写。删除未再使用的 F4 旧路径 E2E 模型；旧断言改为检查路径路由不存在及 P3 ID 路由存在。历史迁移 031 仍描述它当时的旧结构，空库运行到 044 后的最终 schema 已无 `logical_path` 和 `last_operation_id`。
