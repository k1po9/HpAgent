## 已替换的入口与改动模块

- `041_workspace_v41_p0.sql`：`stored_files.conversation_id` 可空，新增 `source_run_id`；`message_files`、`run_files` 与 lineage 改为同账户 FK；Run 文件触发器校验真实 Run、ready 文件与输出来源；新增 `output_publish_operations` 保存发布意图与完成状态。空库迁移保留既有 001–040 初始化及权限管理。
- `FileRepository`、`CommandService`、`RunFileWorkspace`、查询 DTO：按账户和不可变 `file_id` 关联，避免 NULL Conversation 等值 JOIN 丢失合法对象。消息显式选择时才写 `message_files`；失败重试复制原 Run 的固定 `run_files` 并检查当前 ready/选择资格。历史上传可在同 Conversation 再选；已发布输出可在后续 Run 作为 input，原 purpose 不变。
- `FileService`：下载要求同账户、ready 和合法发布依据；发布的 Run 输出不依赖助手消息完成。候选接口只返回分页元数据，输入绑定时重新校验；lineage 按账户查询。Owner 下载接口与 Agent 的 Run 文件读取仍为不同入口。
- `OutputPublisher`、`ResearchMarkdownPublisher`、`TenantFileStore`：确定性 `file_id` 与稳定 operation ID；对象发布前持久化意图，重试校验相同内容，数据库内同时登记 ready 文件、Run 绑定和操作完成。Research 独立 Run 使用真实 Run 发布，无虚构 Conversation/Message。
- Research Task/Run 历史 API 与 Web 入口：可分页寻找已发布输出并下载；聊天可显式选择历史附件或已发布输出。无自动继承、全量 prompt 注入或每轮复制历史对象。`normalized_documents` 原有 `(account_id,run_id,file_id)` FK 保持可用。

## 开发环境重建

本轮没有清空现有开发环境。旧业务数据无需兼容；如果开发者决定重建现有 **app** 数据库，先停止使用它的 API/worker，再明确执行以下命令（会删除 `hpagent` 数据库全部业务数据，不影响本轮隔离库）：

```sh
docker exec hpagent_web-app-postgres-1 sh -lc 'dropdb --force -U "$POSTGRES_USER" hpagent && createdb -U "$POSTGRES_USER" hpagent'
docker compose --profile web up hpagent-migrate
```

隔离测试库由本轮创建，并只在迁移触发器定稿后重置过一次。它可由维护者按需显式删除：

```sh
docker exec hpagent_web-app-postgres-1 sh -lc 'dropdb --force -U "$POSTGRES_USER" hpagent_p0_20260926'
```
