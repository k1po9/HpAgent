## 实施内容

- `043_workspace_v41_p2.sql` 存储 Conversation/Task 通用的资源策略、策略版本、附件可用性、Run 候选快照、选择后的访问依据、固定版本和不含正文的拒绝审计。操作为 `list_metadata`、`read_content`、`create_child`、`update_content`、`delete_entry`；entry 直接授权与 directory 递归授权取并集。新 Conversation 无长期 Workspace Agent 授权。所有者浏览 API 与 Agent Run 权限分开。
- Run 与消息在同一数据库事务中冻结策略版本、拓扑版本和候选节点 ID，完成快照后才产生可分派 Outbox。候选独立于 `run_files`，每 Run 上限 500 项、元数据 512 KiB，超限显式失败。分页只读取固定候选；摘要、claims 和正文不进入候选元数据，也不自动加入 prompt。
- 显式附件在创建 Run 时绑定文件版本；目录候选在首次选择时锁定候选并固定当前版本。并发选择收敛到同一文件 ID。之后重读和恢复使用已固定的 ID，同时重新检查当前授权。多 entry 指向同一对象时每个 entry 留访问依据，同一 Run 只建立一个输入绑定与 logical name。物化按需从 TenantFileStore 进入 Run scope；选择与物化不记作“已读取”，实际受控读取才记录首次读取时间。
- 撤销提交事务先更新策略或附件可用性，核算授权并集，持久化受影响 Run 的取消意图；既有控制面继续推进 `cancelling` 到 `cancelled`。受控读取、选择、重试与长期 `create_child` 提交重新校验权限及 Run 状态。Run 自己已发布的合法输出仍可使用，不能由此扩张外部候选。
- Web 文件工具采用 Run scope 和每次准入检查；文件 adapter、文档规范化缓存结果与发布提交均重新检查。文件工具启用时不暴露宿主 Bash、通用 fs/Glob/Grep、MCP、skills 与可形成旁路的转换工具。进程隔离证据来自实际启用工具集合；`cwd` 或 `chmod` 不作为进程隔离证明。当前这组工具没有开放子进程入口。阻塞 adapter 被取消时，Activity 侧等待线程实际退出后才释放 scope；独立文档子 Workflow 路由被关闭，避免父 Run 取消后继续运行。
- 目录移动/删除的影响预览带拓扑和策略版本令牌；Web API 提交要求该令牌并复核，活动 Run 候选不会因移动而扩大。UI 区分所有者可浏览、长期已授权、Run 候选、已固定与已读取，支持授权、撤销、附件可用性及活动 Run 停止状态。

## 实际撤销保证与边界

- 撤销提交后，新的候选选择、受控读取、工具重新准入和长期提交会失败；重试和恢复不会重新取得已撤销权限。若另一个有效授权仍覆盖同一文件，保留合法访问，不误停相应 Run。
- `cancelling` 表示停止请求已持久化，`cancelled` 表示数据库终态；真实 Temporal 工作流取消和 in-process 工具退出有独立验证。已经返回到模型或外部调用方的内容无法追回；已开始执行的同步 adapter 可能在取消请求后继续运行到退出，期间不宣称已停止。scope 在该操作退出后回收。
- 此轮没有在真实 Temporal 工作流内对**文件工具 Activity**做端到端撤销注入与子进程后代观测；当前启用的 Web 文件工具集合不含宿主 Shell 或其他子进程执行入口。此项是未验收边界，不能把模型或通用 Activity 的取消验证等同于文件工具 Activity 的停止确认。
