## 数据链与限制

- 序号由已授权 Run 记录的账户、source_kind、真实 conversation_id / work_id，按持久化 `(created_at, run_id)` 排序计数。新 Run 是新执行，重试也计数；分页、消息数量、Trace 覆盖、归档不影响编号。以现有保留历史为前提；本次无删除历史、回填时间、写入序号或 schema 迁移。旧 live 快照缺投影时，只读补取同一 Run，响应按对象身份和取消信号隔离。
- 累计量沿用 `run_budgets`；请求次数来自 `run_usage_ledger` 的已结算、在途和已释放尝试，包含重试、fallback 及可能未派发的尝试，界面明确这一口径。输入快照数和 Trace 节点数均不参与累计。
- 带真实 model_call_id 的模型轨迹提供可关联明细；模型／尝试／状态／Token／节点耗时按已有字段显示，缺失如实标注。当前生产埋点通常只保留最终响应，未声称覆盖全部请求；节点耗时是整段跨度，不冒充单次供应商延迟。未根据名称／时间猜关联，未均摊 Token，未增加请求体或凭据权限。
- 输入输出之和与总量一致且总量大于零时才绘制比例；零、缺失、估算、部分覆盖、在途分别表达。预算缺失不画零用量。
- 只读投影将缺失上限保留为 null，区别于真实 0；未知上限不画占用／剩余，真实零预留仍为零，超额文字明确。observe / off 区分于 enforce。
- 接近限制提示根据后端现有最终回复保护额度与输出／总 Token 剩余额度判断，不引入 90% 阈值。保护额度与已预留分开，未推算未来请求次数；未修改计费或预算执行规则。
