# 小白人工验收教程

先用专用验收账号，所有操作只针对自己新建的测试对话和测试文件。不要用已有业务账号、真实 QQ 联系人或重要文件。

## 先打开正确地址

1. 打开浏览器访问 `http://127.0.0.1:8080/health/ready`（不要复制原链接末尾的中文句号）。应显示 `{"status":"ready"}`。
2. 修复后标准前端地址是 [http://127.0.0.1:5173](http://127.0.0.1:5173)，在当前环境统一用这个地址操作。
3. 旧 IP 地址现在会因 Origin 不匹配拒绝写操作；`localhost` 与 `127.0.0.1` 也不是同一 Origin。若访问地址变化，先核对 `WEB_PUBLIC_ORIGIN`；不要自行开全局代理或重启 Docker。
4. 先最大化浏览器。再用 F12 响应式模式检查 390×844：侧栏和聊天应上下排列，控件可操作且不横向溢出；本轮这三个视口 390/768/1440 已补验，Artifact 成果布局仍缺样本。
5. 按 F12 打开开发者工具，点 Network/网络，勾选 Preserve log/保留日志，在筛选框输入 `api/v1`。页面操作时同时记录请求路径、状态码和 Response/响应里的 `request_id`。不要把 Cookie、CSRF token、密码或绑定码复制到公开报告。

## 先看 UI，不调用模型

1. 登录页应有“用户名”“密码”“登录”和“没有账号？注册”。切换注册后应有确认密码和可选邀请码。
2. 用自己新建的验收用户名注册，密码至少 8 位。预期自动登录并提示 QQ 绑定，点“以后再说”。本輪 A/B 两个专用账号均从这个真实页面注册。
3. 左边是对话列表和“新建”；左下是 QQ 状态和退出图标。中间顶部是“持续工作”，下面是“长期 Workspace”和“Research 输出”，聊天框在底部。
4. 点击“持续工作”。空账号应显示“暂无持续委托”。点击“Research 输出”：加载时显示“正在加载调查委托…”，成功为空后应解释“暂无调查委托或成果”。失败应显示加载错误，不能冒充空列表。
5. 不选择对话时应显示“选择或新建一个对话开始”。点左上“新建”，应出现“新的对话”“开始新的对话吧”，底部可输入文字；没有文字时发送应不可用。
6. Workspace 内部会滚动。向下滚动它可以找到目录操作、授权、保留原因和版本控件。不要把看不到下半部分误认为没有入口。
7. 有 Run 时，“Trace”可打开右侧执行树；空对话 Trace 应禁用。当前没有独立“记忆管理”“收件箱全文”“Research 参数编辑”面板。

## 文件、Workspace 与授权

1. 在本机新建 UTF-8 文本文件 `manual-acceptance.txt`，内容如下；这不是业务数据。

   ```text
   验收文件
   代号：FILE-482
   数值：17
   ```

2. 在“长期 Workspace”点“资料”，再点“上传到 Workspace”的文件选择按钮，选刚建的文件。预期出现文件入口。
3. 网络应依次出现 `POST /workspace/uploads` 201、`PUT /uploads/{id}/content` 200、`POST /workspace/files` 201。上传到 Workspace 不应偷偷新建对话或消息。
4. 点文件旁的“下载”，打开下载文件，应与上传文件内容一致。换行编码可能因编辑器不同而不同，比较的是自己的上传和下载；本轮 LF 测试样本为 43 bytes，SHA-256 已保存。
5. 点文件本身，预期显示来源、大小、保留说明、“当前版本：不可变入口”。点“启用版本历史”，应出现当前版本 1 和 v1 下载链接。**这只验证 v1，不能当作新版本提交已通过。**
6. 在“名称”输入新的测试名称，点“预览改名或移动影响”，检查影响提示，再点“确认改名或移动”。预期 ID 和文件内容不变，展示名称改变。
7. 在搜索框输入新文件名，点“搜索”，应找到该文件；空结果目前没有清楚的空状态文字。
8. 在文件上点“授权当前对话读取文件”。应显示 `list_metadata`、`read_content` 两条规则，网络 `POST /conversations/{id}/resources` 201。
9. 逐条点“撤销”，预期授权数回到 0，页面说明无需停止活动 Run。网络 DELETE 200，重新 GET resources 应无有效规则。
10. 当前 UI 只提供读取、修改文件等部分授权，没有任意五种权限的完整编辑器。拥有文件、能下载文件和 Agent 被授权读取是不同事实。
11. 只对新建的测试 entry 测移除：点“预览移除影响”再“确认移除”。预期入口消失；若文件还有消息/Run/历史版本引用，物理 bytes 不应马上减少。不要删除原有目录或业务文件。

## 对话、附件、切换和刷新

1. 新建测试对话 A，再新建测试对话 B。左右切换 A→B→A，最后应显示 A 的消息，不能串入 B。
2. 附件入口在底部“附件”。选择小文本，应显示“已就绪”。发送前可以移除，或展开“选择已有文件”选已有资料。
3. 发送带附件的短消息后，网络应为 `POST /conversations/{id}/messages` 202，消息应有文件链接。202 只说明已接受，不代表模型执行成功。
4. 要测排队取消，发送后立即点“停止”。网络应有 `POST /runs/{id}/cancel`，再 GET Run 必须到 `cancelled`，页面也应显示已停止，资源区不再报“资源授权加载失败”。状态依赖 SSE/恢复查询，不能只凭按钮变灰判定通过。修复后新样本已确认 API/UI 终态、0模型请求及刷新恢复；运行中停止仍须另验。
5. 刷新页面应恢复账号、对话列表、已持久化消息与附件。当前刷新自动选择最新对话，**不会保存刷新前选中的旧对话**；再点 A 可以恢复 A 的记录。
6. 在消息文件旁点“保存到 Workspace”，会保存到当前选中的目录。它与上传/发布是不同请求。可以随后移除新 entry；消息文件仍可能因引用保留。
7. 在资源面板点“撤销附件可用性”，应从对话可用资料移除。过去消息的文件引用不因此被物理删除。

## 真实模型：当前阻断，恢复后每项只做一次

当前真实聊天已复现模型超时。不要反复点击“重试”，先解决模型访问问题，再执行以下小输入。

1. 在 A 发送：“这是验收测试，请仅回复：验收成功。不要调用外部工具。”
2. 网络 202 后应经历 queued/running，最终 Run `succeeded`、助手消息 `completed`，正文为预期回复。打开 Trace，应有真实模型调用；工程人员要对照同一 Run 的模型快照、dispatch、额度账本和终态。
3. 初次短记忆暗号输入最终 `failed / model_unavailable`。修复后失败条增加服务端安全说明与错误码；真实新失败提示仍待模型场景复验。Trace Metadata 可查错误码。**failed 是失败，不能当作完成。**
4. 若要测运行中停止，等 Trace/进度显示调用模型或执行工具后再停止；必须确认模型/工具退出、Run 取消和无后续未授权发布。本轮只测了 queued 取消，运行中取消未验证。
5. 计划执行也必须产生最终助手成果及真实步骤证据；下拉框能选“计划执行”不算通过。

## 持续工作

1. 真实模型恢复后，在聊天里明确委托：“接受一项测试持续工作，一分钟后把 TEST-WORK-01 提醒存入本账号 Web 收件箱，不使用 QQ；请返回已接受的 Work ID。”
2. 应看到已持久化 Work ID，“持续工作”中出现对应委托。只回复“已安排”但没有真实 Work 是失败。
3. 对尚未到期的新测试 Work，点“暂停工作”，应变“已暂停”；点“恢复工作”，应回“持续履行”；需要取消时点“停止工作”，应到“已停止”。停止后不得再产生履约投递。
4. 另建一项立即提醒，让它实际运行。预期独立 Run `succeeded`，Work `completed`，页面显示“已存入收件箱”，后端有 `account_inbox_committed` 回执和包含测试标记的 notification。
5. 本轮用验收 API 创建两条测试 Work（不是 UI 自然语言创建），控制按钮和立即提醒真实履约通过；没有模型参与，不能据此认定 Generic Work 能生成成果。
6. Network 中 Work SSE `/events/stream` 应为 200，响应类型为 text/event-stream；普通 `/events` 应为 JSON 200。修复后已收到真实事件并通过游标续读。停止的 Work 应显示不再继续执行，不再显示等待未来到期；若只靠列表轮询变化不能签收 SSE。

## Research、文档、Artifact 与记忆

这些成果场景当前没有算作通过。模型/配置恢复后执行一次小样本，按结果验收。

| 场景 | 怎么操作 | 必须看到什么 |
|---|---|---|
| Research | 聊天明确委托一次小调查，例如“调查 Python 的一个基础概念，仅用少量来源，生成带引用的短报告，返回 Work ID” | research_report Work、真实查询/获取/证据、报告、成功 Run、发布文件；有 required 保存时还需 Workspace 保存成功。打开 Research 输出查看全文/下载，不能只有列表 |
| 文档创建 | 聊天要求生成一页含 TEST-DOC-01 的 DOCX | 真实生成工具 operation、published file、可下载且能打开的 DOCX，内容含标记 |
| 文档转换/规范化 | 只在相关能力开启后，用新测试 Office/PDF 文件请求转换 | document Worker 实际完成 operation、结果文件和预算结算；当前 transform 关闭，不能仅凭 Worker running 算通过 |
| Artifact | 有已完成助手消息后点“生成 Artifact”，完成后预览，再用小指令编辑一次 | Artifact-build Work/Run、version completed、实际预览内容；v2 与 v1 分开，来源/成本可追溯 |
| 记忆 | A 发送“记住我的测试暗号是青竹739”；确认 completed 且后端 retain 成功，再新建 C 问“我的测试暗号是什么”，不在 C 重复暗号 | account bank 真实保留及召回证据、C 回答正确；同一对话复述不能证明长期记忆 |
| 撤权 | 仅测试文件，先让真实 Run 选择/读取，再撤销最后一个有效 read_content | 新访问被拒、持久化 cancel intent、执行端停止、无未授权输出；`stopping` 不等于 stopped |
| v2/CAS | 对可更新 entry 选择真实 Run 已发布输出，提交新版本 | v2 字节符合预期、v1 可下载；并发冲突不得覆盖当前版本，旧输出可另存 |

Research 的参数/定时/Work 输入授权没有独立完整表单；部分配置可通过 Main Agent 和 API 表达，但本轮没有真实执行证明。Artifact 没有完成的助手输入，文档转换关闭，长期记忆 recall 超时且没有 completed 聊天可供保留：均为“未验证（阻断）”。

## 账号隔离和 QQ

1. 另开无痕窗口，注册专用账号 B，不要复用 A 的浏览器 Cookie。B 应看不到 A 的对话、文件和 Work。
2. 记录 A 的测试文件下载地址，在 B 窗口访问它，应返回 404。对 A 的 conversation、Run、版本、Trace、Work 也应返回 404。本轮已检查九种 GET 和一项跨账号授权写入。
3. B 点退出图标，应回登录页，`GET /me` 401；A 窗口仍应保有 A 会话。通过 UI 正常提交的请求有 CSRF；移除 CSRF 的测试请求应 403，不应创建数据。
4. QQ 仅测试“绑定 QQ”生成挑战、页面说明和过期状态。**本轮没有向 QQ 发送绑定指令或消息**。如需完成绑定，要先提供获准使用的测试 QQ 身份，由本人发送页面指令并检查账号合并/记忆归属；完成前标“未验证”。
