# HpAgent 登录转场对比实验

独立 Vite / React 原型，不引用 `web/src`，不调用认证接口，不修改生产构建入口。按照 v1.2 设计基线制作两种可实际运行的视觉对照，共用相同 Auth / App Shell 和时间轴。工作台为代表性布局，尚未与现有 HpAgent 组件集成。

## 启动

```bash
cd prototypes/auth-transition
npm ci
npm run dev
```

打开 http://localhost:5310，选择方案，点击「模拟登录成功」。通过「重置演示」重复比较。需要其他端口时运行 `npm run dev -- --port 5311`。

```bash
npm run build
npx playwright install chromium # 首次运行测试需要浏览器
npm test
```

依赖使用独立 lockfile。本次因 npm 官方源连接超时，安装使用 npm 镜像源；lockfile 保留实际下载地址。

## 比较什么

| 方案     | 实现                           | 视觉重点                                                       | 注意事项                                                                               |
| -------- | ------------------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 粒子解构 | GSAP Timeline + 原生 Canvas 2D | 卡片边缘中性微粒沿受控曲线流向导航、侧栏、主画布，少量暖色微粒 | Codrops 风格参考，不是复制特定 Codrops 示例；不是 DOM 像素截图拆解                     |
| 空间变形 | GSAP Timeline + Flip           | 同一 DOM 表面由登录卡片变为输入区域，骨架依次出现              | 本轮刻意验证卡片→Composer 的强几何连续性；基线建议的 Auth→Main Canvas 映射仍需设计评审 |

建议先看默认 1280ms，再比较 900 / 1600ms。没有引入 Motion、Three.js、WebGL 或旧 React 粒子库。字体使用系统字体，无外部字体或图片请求。

## 时间轴与收尾

正常时间轴总长按 900 / 1280 / 1600ms 缩放：

- 0%：身份已确认；14% 开始退出表单。
- 18%：边缘微粒启动；20%：卡片用缩放/透明度消散；Flip 在 22% 开始变形。
- 28%：App Rail；38%：Context Sidebar；48%：Main Canvas。
- 54%：登录表面退场完毕；60%：输入框表面承接；66%：首屏内容；76%：输入框内容；94%：归于安静；100%：稳定。

Workbench 从初始状态就挂载，终点不重新挂载。过渡期间使用 `inert` 阻止不可见界面被键盘访问，完成后焦点进入输入框。完成后移除 Canvas、取消测量 RAF；GSAP 由 `@gsap/react` 的 context 在重置/卸载时回收。没有闲置粒子循环。取消按钮可以中途卸载并重置原型。页面进入后台、视口变化或系统改为减少动态效果时立即稳定到终点。

`prefers-reduced-motion: reduce` 或手动开关使用 160ms 无位移淡化，无 Canvas。减少动态效果的时长有意不遵循品牌级 900–1600ms 区间。

## 性能验证方法

- 标准：168 个 1–3 CSS px 粒子，Canvas 像素密度上限 1。
- 低功耗：48 个粒子，Canvas 像素密度上限 0.75（以少量锐度换取较低绘制面积）。
- 自动：逻辑核心数 ≤4 或可用 `deviceMemory` ≤4GB 时选择低功耗；这只是启发式预算，不代表设备实际速度。
- 页面记录从动画准备开始到收尾的墙钟时间（包含路径预计算；悬停时长可看准备耗时）、RAF 帧间隔 P95、超过 33.4ms 的帧数、样本总数与实际粒子预算。系统调度会影响墙钟时长，900/1600ms 边界不应视为硬实时承诺。
- Playwright 覆盖正常结束、两种系统减少动态效果、手动降级、反复取消、移动视口、时长预设和 Chromium 4× CPU 降速。
- CPU 降速不模拟移动 GPU、发热、内存压力、刷新率和触屏浏览器。真机低性能验收仍需现场比较；不得把低预算模式或模拟测试等同真机通过。

视觉通过后再确定主表达，并将模拟成功事件替换为真实认证成功回调；等待数据/认证的耗时应与视觉时间轴分开管理。

## 当前方向与验证记录

用户于 2026-10-10 表达倾向粒子方案，因此粒子解构作为后续主视觉方向，Flip 留作对照；尚未接入真实认证。

构建与 8 项 Playwright 测试通过，包括新增的中途系统降级及 Canvas 残留像素/重复释放检查。测试通过表示交互、收尾和降级行为符合断言，不等同视觉或低性能验收通过。

## 本轮优化（2026-10-10）

- 卡片不再逐帧改变 `clip-path`，使用透明度和轻微缩放退场；导航、侧栏和主画布提前出现，衔接输入框表面，减少消散后的空档。
- 微粒按导航 / 侧栏 / 主画布 / 输入框分组，落到布局边界，移动端跳过隐藏侧栏；不再流向大面积随机落点。
- 预计算 81 组 `Path2D`，动画帧最多 8 次批量填充，不在逐帧路径中计算三角函数或读布局；只清除上一帧实际边界区域。
- 减少粒子与 Canvas 像素密度，阶段提示直接更新文本，避免每个阶段重新协调整棵 React 场景。
- 临时 `will-change` 只存在于过渡期；完成、重置和中断时取消测量循环、释放路径缓存和 Canvas backing store，恢复键盘焦点。
- 将准备阶段计入页面的实际时长，防止预计算成本被隐藏。减少动态效果时不创建粒子画布和路径缓存。

`node benchmark.mjs before` / `node benchmark.mjs after` 可采集不录像的重复测量；文件名标签只标记输出，**不会自动切换代码版本**。每个场景先预热 1 次，再记录 5 次；固定 1440×1100，分别测正常标准、4× CPU 标准、4× CPU 低功耗。基准输出保存在 `evidence/benchmark-*.json`。

`node capture.mjs` 单独采集视觉证据（会覆盖 `evidence/` 中的截图、录像和 `metrics.json`）。录像运行的数据不得与无录像基准混用。

### 无录像重复测量结果

每格 P95 为五次运行各自 P95 的中位数；长帧为所有样本中 >33.4ms 的占比。优化前后为同一共享执行环境的顺序测量，存在调度波动，不能据此保证真机帧率。

| 场景            | P95 优化前 → 后 | 长帧占比前 → 后 | 优化后总时长中位数 | 准备开销中位数 |
| --------------- | --------------- | --------------- | ------------------ | -------------- |
| 1× CPU / 标准   | 33.3 → 33.3ms   | 1.1% → 0.9%     | 1266ms             | 7ms            |
| 4× CPU / 标准   | 50 → 49.9ms     | 11.3% → 10.5%   | 1227ms             | 54ms           |
| 4× CPU / 低功耗 | 66.6 → 33.4ms   | 16.8% → 3.8%    | 1214ms             | 26ms           |

总时长以 1280ms 为目标；优化后已包含准备开销，旧版统计起点较晚，因此不直接计算前后总时长提升比例。GSAP 时钟与浏览器调度会使实际时长偏离目标。

低功耗方案在本轮无录像测量中改善明显，标准方案改善有限。视觉证据采集脚本另一次低预算单次测量仍出现 116.6ms P95，说明共享环境、浏览器及录制流程残留负载会显著影响结果。**当前不认定低性能验收通过，也不承诺 60fps**；需要在目标真机上关闭录像重复复测。当前仍是独立原型，不接认证。

## Cookie 恢复入口与正式接入

新增第三个方案「Cookie 恢复」：选择快速成功、慢请求、Cookie 过期或网络失败，再点击「模拟 Cookie 恢复」。圆环成功后释放沿圆周采样的微粒；过期进入登录表单，失败显示重试。该实验室仍使用模拟事件。

同一视觉方案已移植为正式 `web` 入口（5173）的 TypeScript 组件，接入实际身份验证与会话生命周期，详情见 [接入说明](../../docs/implementation/auth-entry-transition-2026-10-10.md)。实验室保留独立依赖与实现，用于比较效果；本文前面的历史性能记录不代表正式集成版本的真机验收结论。
